# نظام البصمة - التوضيح والربط 🔗

## الفرق بين الحقول:

### 1. `AC-No.` (كود البصمة)
- **المصدر**: جهاز البصمة الحقيقي
- **التنسيق**: كما يرسله الجهاز (مثل: "1", "2", "100000")
- **الاستخدام**: للربط مع بيانات جهاز البصمة
- **مثال من الجهاز**: 
  ```
  AC-No. Name Date Clock In Clock Out
  1      Agg  2025-08-23 08:00 17:00
  2      Samir 2025-08-23 08:15 17:30
  ```

### 2. `fingerprint_id` (معرف البصمة الداخلي)
- **المصدر**: النظام الداخلي
- **الاستخدام**: للبحث والمطابقة داخل النظام
- **الربط**: يجب أن يكون مطابق لـ `AC-No.`

### 3. `fingerprint_enrolled` (مسجل في البصمة)
- **القيم**: 0 = غير مسجل، 1 = مسجل
- **الاستخدام**: لتحديد إذا كان الموظف مسجل في جهاز البصمة

### 4. `fingerprint_device_id` (معرف جهاز البصمة)
- **الاستخدام**: لتحديد أي جهاز بصمة يستخدمه الموظف
- **الربط**: مع جدول `fingerprint_devices`

## التحديثات المطبقة:

### 1. في `fingerprint_sync.php`:
```php
// البحث عن الموظف باستخدام AC-No. أو fingerprint_id
WHERE (`AC-No.` = ? OR fingerprint_id = ?) AND status = 'active'
```

### 2. في `fingerprint_system_integration.php`:
```php
// إضافة AC-No. عند إنشاء موظف جديد من البصمة
INSERT INTO employees (
    employee_code, 
    `AC-No.`,        // ← تم إضافة هذا
    name, 
    department, 
    status, 
    fingerprint_id,
    fingerprint_enrolled,
    created_at
) VALUES (?, ?, ?, ?, 'active', ?, 1, NOW())
```

## كيفية العمل:

### للموظفين الجدد:
1. **من جهاز البصمة**: `AC-No.` = "1", `fingerprint_id` = "1"
2. **من النظام**: يمكن إدخال `AC-No.` يدوياً، `fingerprint_id` = `AC-No.`

### للموظفين الحاليين:
1. **إدخال `AC-No.`**: من خلال مودال تعديل بيانات الموظف
2. **تحديث `fingerprint_id`**: تلقائياً ليطابق `AC-No.`

## التوصيات:

### 1. للموظفين الحاليين:
- إدخال `AC-No.` لكل موظف من خلال مودال التعديل
- النظام سيربط `fingerprint_id` تلقائياً

### 2. للموظفين الجدد:
- إدخال `AC-No.` عند إضافة الموظف
- النظام سيربط `fingerprint_id` تلقائياً

### 3. لجهاز البصمة:
- النظام يبحث عن الموظف باستخدام `AC-No.` أولاً
- إذا لم يجد، يبحث باستخدام `fingerprint_id`
- هذا يضمن التوافق مع جميع السيناريوهات
